# Сборка и публикация QLens (ранее QuestItemQuests)

## Первичная настройка

1. В `release-config.json` уже указан предоставленный владельцем существующий CurseForge Project ID **1734956**. Новый проект создавать не нужно.
2. Секрет репозитория `CF_API_KEY` уже создан. Workflow передаёт его только шагу публикации как `CF_API_TOKEN`; значение токена не нужно добавлять в файлы.
3. Подтверждённая владельцем ручная загрузка `1.0.0` уже внесена в `previously_published_versions`. Новые ручные загрузки также добавляйте в этот список. Маркеры workflow защищают последующие автоматические публикации.
4. В GitHub Settings → Environments создайте `curseforge`. Если требуется подтверждение каждого релиза, настройте Required reviewers (доступность зависит от тарифа). Само имя environment в YAML не включает обязательное одобрение.
5. Разрешите GitHub Actions. Политики репозитория должны позволять `GITHUB_TOKEN` создавать ветки `curseforge-releases/*` для постоянных маркеров отправки.

## Что запускается автоматически

- Push в `main`, pull request в `main` и ручной Run workflow: проверка исходников, Lua 5.1, генерация английского changelog, сборка BigWigsMods/packager@v2 **без публикации**, проверка ZIP и сохранение Actions artifact на 90 дней по стандартным настройкам GitHub (либо по политике репозитория).
- По решению владельца все последующие публикации в CurseForge имеют тип **Release** (`releaseType: release`). Alpha/Beta больше не выбираются автоматически даже при старом суффиксе версии. Уже опубликованные файлы не изменяются.
- Push тега `vX.Y.Z`: те же проверки, затем публикация в CurseForge. Старые форматы `vX.Y.Z-alpha.N` / `vX.Y.Z-beta.N` распознаются для совместимости, но также используют тип Release. Версии обоих TOC должны совпадать с тегом без `v`; коммит должен принадлежать истории `origin/main`. Другие теги, начинающиеся с `v`, завершатся ошибкой проверки. `workflow_dispatch` никогда не публикует, даже при выборе тега.
- Архив содержит две папки рядом: `QLens/` и `QLens_Guide/`, включая их TOC, Lua, README и сведения об источниках данных. Changelog сохраняется рядом как Actions artifact и передаётся CurseForge при публикации. `.pkgmeta` поднимает оба модуля на верхний уровень ZIP. Скрипты CI, настройки и документация релиза в ZIP не попадают.

Для следующего выпуска используйте обычную версию без alpha/beta, например `2.0.0`. Обновите `## Version` в TOC обоих модулей, `A.version` в `QLens/Locale.lua` и номер в README. Отправьте изменения в `main`, дождитесь успешной сборки. Версия `2.0.0-alpha.6` уже была загружена как Alpha до изменения этой политики; её тег не переиспользуйте. **Только после решения публиковать** выполните, подставив свою новую версию:

```sh
git tag vX.Y.Z
git push origin vX.Y.Z
```

Не переиспользуйте и не перемещайте опубликованные теги. Workflow не создаёт GitHub Release.

## Forever и проверка публикации

Целевая игра — только Forever `1.60.1`, TOC `16001`. Packager v2 поддерживает `forever`/`camelot`, включая `-g 1.60.1`. В его исходниках CurseForge `gameVersionTypeID` для Forever равен **88568** (это тип игры, а не ID версии).

Перед загрузкой скрипт запрашивает `https://wow.curseforge.com/api/game/wow/versions` и выбирает единственный положительный `id` с `name == "1.60.1"` и `gameVersionTypeID == 88568`. Каталог требует токен; локально без секрета сервер вернул 401. Числовой ID версии намеренно не выдуман и не зафиксирован. При отсутствии точного совпадения публикация останавливается. Retail (`517`) и Classic (`67408`) не подходят.

`release.sh` читает `CF_API_TOKEN`, а `CF_API_KEY` оставляет как устаревший fallback. Здесь Packager запускается с `-d` без секретов. Отдельный Python-шаг отправляет **тот же проверенный ZIP** в официальный Upload API: это исключает fallback Packager на другую версию и повторные POST-запросы при сбоях сети. GitHub/Wago/WoWInterface-публикации не выполняются.

Changelog создаётся автоматически на английском по изменённым файлам и списку коммитов от предыдущего достижимого тега `vX.Y.Z`. Это техническая сводка категорий изменений, без перевода или копирования русских commit messages; она не пытается угадать смысл изменений игровой логики.

## Защита от повторной отправки и восстановление

Все publish jobs используют одну concurrency group с `cancel-in-progress: false`. GitHub сохраняет один выполняющийся и один ожидающий запуск; при нескольких быстрых тегах старый ожидающий job может быть заменён новым. Поэтому выпускайте по одному тегу; отменённый ожидающий запуск можно повторить после текущего.

Перед POST в CurseForge атомарно создаётся ветка-маркер `curseforge-releases/vX.Y.Z` на коммите релиза. Если маркер уже существует, отправки не будет — даже после rerun, удаления/пересоздания тега или потери ответа сервера. Автоматических повторов POST нет. Ветки-маркеры нельзя удалять при обычной уборке репозитория.

При ошибке после создания маркера сначала проверьте Files в CurseForge, включая файлы на модерации, и лог Actions. Если загрузка уже принята, оставьте маркер. Только убедившись, что файла нет, вручную удалите соответствующую ветку-маркер и повторите job. При неопределённом результате не удаляйте маркер. Новые ручные загрузки также добавляйте в `previously_published_versions`; обход workflow не покрывается автоматической блокировкой.

## Локальная проверка без публикации

Нужны Python 3.12 (работает также 3.11), Git, Bash, Lua 5.1 (`luac5.1`), zip и официальный checkout BigWigsMods/packager v2. Для Windows без `luac` проверяющий скрипт поддерживает `lupa.lua51`.

```sh
python -m unittest discover -s tests -v
lua5.1 tools/verify_build.lua
lua5.1 tests/run.lua
lua5.1 tests/guide.lua
python scripts/release.py prepare
bash /path/to/packager/release.sh -d -e -l -u -g 1.60.1 -w 0 -a 0 -n 'QLens-{project-version}'
python scripts/release.py verify
```

Packager собирает отслеживаемые Git файлы: новые файлы предварительно добавьте в индекс. Используйте чистый каталог `.release` без ZIP от прежних сборок. `prepare` и `verify` не обращаются к сервисам публикации. Проверка исходников/ZIP компилирует Lua без выполнения, проверяет TOC, регистр путей, содержимое и структуру архива; проверка в игровом клиенте остаётся отдельной задачей.

Источники: [Packager](https://github.com/BigWigsMods/packager), [release.sh v2](https://github.com/BigWigsMods/packager/blob/v2/release.sh), [CurseForge Upload API](https://support.curseforge.com/support/solutions/articles/9000197321-curseforge-api).
