# Технический аудит QuestItemQuests 1.4.1

Дата аудита: 2026-10-09. Цель: WoW Forever 1.60.1, Interface 16001. Исходная версия сохранена: номер релиза не менялся.

## Подтверждённые дефекты и исправления

- Проверка `mask ~= 64` верно классифицировала все девять масок, реально встречающихся в текущем snapshot. Именованные биты добавлены как усиление схемы и защита будущих комбинаций: objective=1, source=2, required=4, startedBy=8, startQuest=16, related=32, reward=64. Маска 64 не открывает квест; 66 сохраняет source-связь и поэтому остаётся действующей.
- Точные цели журнала индексировались с учётом регистра. Теперь названия предметов, целей и русские заголовки проходят общую нормализацию ruRU; текст цели нормализуется один раз при перестроении.
- В текущем статическом snapshot дублей questID внутри предмета нет. Для устойчивости добавлена явная дедупликация статических строк; динамические и специальные связи уже дедуплицировались существующей логикой.
- `__QIQLink` не учитывал состояние журнала, а resolver выполнялся до проверки маркера. Добавлен кеш по itemID и нормализованному имени с ревизией журнала. Он инвалидируется при изменениях заданий и загрузке item info.
- Открытая подсказка могла устареть и повторно добавлять строки. Аддон теперь рисует собственную companion-подсказку и обновляет только её; исходный tooltip других аддонов не очищается и не переписывается. Companion закрепляется сверху или снизу с учётом доступного места и ограничивается экраном.
- `tooltip:GetItem()` отдавал имя, но использовалась только ссылка. Имя теперь участвует в разрешении; pending-состояние сохраняет itemID до `GET_ITEM_INFO_RECEIVED`, после чего повторяется полноценное разрешение, включая dynamic-only цели без статической связи и classID.
- TooltipDataProcessor может передать owner, которого не было при загрузке аддона. Такой owner лениво получает только lifecycle hooks `OnHide`/`OnTooltipCleared`; после скрытия tracking удаляется, поэтому события журнала не оживляют закрытую companion-подсказку.
- При смешанном списке отношений tooltip показывал отдельные reward-only квесты рядом с действующими отношениями. Теперь при наличии хотя бы одной actionable-связи выводятся только actionable-квесты; reward-only список показывается лишь отдельно и только для quest-class предмета. Маска 66 остаётся actionable.
- Список tooltip-объектов через `ipairs` обрывался на первом `nil`. Каждый поддерживаемый tooltip подключается отдельно.
- `pcall(QuestMapFrame_OpenToQuestDetails)` считался успехом даже при явном `false`. Для одиночного задания ошибка и `false` возвращают управление стандартному обработчику. В меню нескольких заданий неудача оставляет меню открытым и выводит короткую диагностику, позволяя выбрать снова.
- Shift-клик мог перехватываться при вводе текста. Проверяются оба доступных в Forever API: `ChatEdit_GetActiveWindow` и `GetCurrentKeyBoardFocus`, с защитой `pcall`.
- Ошибка метода сторонней bag-кнопки могла оборвать глобальный обработчик. Весь код перехвата аддона теперь выполняется fail-closed: при ошибке исходный `HandleModifiedItemClick` вызывается ровно один раз с неизменными аргументами. Сам исходный обработчик не обёрнут в `pcall`, поэтому его собственные ошибки не скрываются.
- Автор в TOC исправлен на Evilion.

## Данные и ложные срабатывания аудита

Маски не являются форматом QuestieDB. Это собственный компактный формат генератора. Исходные поля установлены по `QuestieDB.questKeys` и `QuestieDB.itemKeys`, а генератор больше не использует безымянные числовые позиции.

Для QuestieDB Forever commit `e0a6eaa86f181ac99262e34126bcd2ed1a1712d6` подтверждено: 4 777 itemID, 7 389 отношений, 2 251 предмет класса 12; пропущенных названий и дублей questID внутри предмета нет. Маски: 1=3324, 2=843, 4=63, 6=6, 8=28, 9=4, 10=174, 64=2945, 66=2. Маски 16 и 32 в текущем снимке не встречаются, но поддерживаются и тестируются. Само наличие бита 64 не означает ложную связь: у маски 66 одновременно есть source=2.

QuestieDB не загружается игрой и не является внешней зависимостью релиза. Она используется только для офлайн-генерации `QuestItemQuestsData.lua`. Файл данных не редактировался вручную и воспроизводимо перегенерирован.

## Проверка

`tests/validate_data.lua` проверяет положительные целочисленные ID, маски, дубли, названия, количество записей и распределение масок. `tests/run.lua` использует mock WoW API и покрывает: одно и несколько активных заданий, отсутствующее задание, reward-only, смешанные отношения и mask 66, маски 8/10/16/32 в resolver и tooltip, неизвестный quest item, смену журнала, поздний dynamic-only GetItemInfo, русское сравнение без учёта регистра, дубли, геометрию и clamp companion, обычный и неизвестный клик, обе ветви определения чата, ошибку/false открытия одиночного задания и каждого пункта multi-menu, успешный Shift-клик и nil-разрывы в tooltip-списке.

## Оставшиеся ограничения

- Без запущенного клиента нельзя подтвердить геометрию companion-tooltip во всех UI scale и с каждой сборкой сумок.
- Глобальная обёртка `HandleModifiedItemClick` сохранена: доступного в Forever cancellable pre-hook API не найдено, а `hooksecurefunc` вызывается после стандартного действия. Обёртка fail-closed и передаёт исходной функции все неподходящие и ошибочные случаи, но конфликт с другим аддоном, который позднее заменит функцию, возможен.
- Успешный вызов API с `nil` не доказывает визуальное открытие карты; это проверяется вручную. Явный `false` и Lua-ошибка обработаны.
- Эвристика доставки по двум первым словам и глаголу остаётся ограниченной локализацией. Она сохранена ради существующего поведения и может требовать пополнения словаря.
- Пользовательские bag UI без bag/slot в кнопке безопасно передаются стандартному обработчику и не открывают квест.
